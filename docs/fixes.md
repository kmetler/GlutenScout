* Usability Top 10 that professor Twyman is looking for  
  **1 Signify capability** \- With Lara’s suggestions there will be better signifiers on each page  
  **2 Easy wayfinding** \- The navbar helps with this, but Lara pointed out that discovery and meal feels like the same thing  
  **3 Guide attention** \- I think we do this well, but want to get other’s opinions. According to this principle we should use contrast and visual hierarchy, as well as think “what is the most important thing and how can we better guide the user's attention on each page”.   
  **4 Follow Conventions** \- By using Yelp’s design guide, I think we are doing a good job at this.  
  **5 Timely feedback** \- I think that our app is quick and does not give a lot of feedback (by design and because it is a prototype), so we could add spinners when loading things and maybe even animate our page transitions (like having things slide in and out of frame)

***Here is the rubric***

* All instructions are followed.  
  * ✅The prototype looks low fidelity from the perspective of the user, and the user is explicitly told the prototype is in early stages (e.g. with a modal).  
  * ❌For any screen where a user might first enter the solution (e.g., when they first open the app or first encounter the website), the overarching capability of the solution is the first and most prominent thing signified. Other top-level functions are signified in a manner consistent with signifying principles taught in class.  
  * ❌The design follows conventions internally and externally, effectively guides user attention, uses effective grouping, and generally implements all usability principles covered in class thus far.  
  * ✅The design uses a design library, reusing components rather than building everything piecemeal. The design library seems to match the affordances and root user outcomes identified in discovery research.  
  * ❌The website or app is fully functional, except for any core backend features that cannot be readily vibe-coded. There should NOT be one single path for the user to follow. The user should have a goal in mind (a goal should be given to them up front in a modal or in instructions), but there should be multiple possible routes for the user to take. If onboarding is used, the user is able to skip it.
